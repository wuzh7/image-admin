# 订单明细外部接入与后台管理设计

## 1. 背景与目标

系统上线后需要接收外部调用方提交的订单明细，并为管理员提供订单明细查询、查看、新增、修改、删除和 Excel 导出能力。

本功能目标：

- 提供使用独立 API Key 鉴权的外部批量写入接口。
- 兼容 `excel插入新功能/请求数据格式.txt` 中的嵌套请求结构。
- 按子订单号实现幂等写入，调用方重试不得产生重复明细。
- 提供仅超级管理员可访问的订单明细管理页面和管理接口。
- 按参考 Excel 的表头及列顺序导出当前查询结果。
- 对管理员操作和外部导入结果留下可追踪日志。

## 2. 不在本次范围内

- 不提供普通用户或其他角色的订单数据权限配置。
- 不提供 Excel 导入。
- 不提供订单状态流转、统计报表、物流跟踪或图片下载。
- 不在后台页面维护或展示 API Key。
- 不保存外部请求的完整原始 JSON。

## 3. 总体架构

新增独立 Maven 业务模块 `wuzh-order`，由 `wuzh-admin` 引入。模块内部按现有项目风格划分为 controller、service、mapper 和 domain。

采用单张订单明细表。每个子订单保存为一行，主订单级字段随明细重复保存。该结构与后台列表及 Excel 的扁平结构一致，避免为当前需求引入主表、明细表联查和级联编辑。

主要组件：

- `OrderDetailOpenApiController`：外部批量接入入口，只负责 API Key 校验、参数校验和响应组装。
- `OrderDetailController`：管理员 CRUD、分页查询和 Excel 导出入口。
- `OrderDetailService`：请求展开、金额转换、父子订单一致性校验、幂等写入和事务控制。
- `OrderDetailMapper`：MyBatis-Plus 数据访问。
- React 管理页面：查询表单、分页表格、详情/编辑弹窗、图片预览和导出。

## 4. 数据模型

表名：`ord_order_detail`

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| id | bigint | 主键 | 雪花 ID |
| parent_order_sn | varchar(64) | 非空、索引 | 主订单号 |
| fulfillment_mall_id | varchar(64) | 可空、索引 | 店铺 ID，按标识符保存，避免数字精度丢失 |
| estimated_amount | decimal(12,2) | 可空 | 运费金额 |
| send_warehouse_name | varchar(128) | 可空、索引 | 下单工厂 |
| shipping_company_name | varchar(128) | 可空、索引 | 物流商 |
| order_sn | varchar(64) | 非空、唯一索引 | 子订单号，幂等键 |
| goods_name | varchar(1000) | 可空 | 商品名称 |
| sku_quantity | int | 非空 | 数量，必须大于 0 |
| spec | varchar(512) | 可空 | SKU/规格 |
| thumb_url | varchar(1000) | 可空 | 图片地址 |
| create_by | bigint | 可空 | 管理员新增时记录用户；外部接入为空 |
| create_time | datetime | 非空 | 创建时间 |
| update_by | bigint | 可空 | 管理员修改时记录用户；外部接入为空 |
| update_time | datetime | 非空 | 更新时间 |

不启用逻辑删除。管理员删除后数据直接移除，并由系统操作日志保留删除记录。

## 5. 外部接口

### 5.1 请求

- 方法：`POST`
- 路径：`/open-api/order-details/batch`
- 请求头：`X-API-Key: <调用密钥>`
- Content-Type：`application/json`
- 请求体：订单数组，结构与参考文档一致。

父订单对象字段：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| parentOrderSn | string | 是 | 主订单号 |
| sendWarehouseName | string | 否 | 下单工厂 |
| fulfillmentMallId | string | 否 | 店铺 ID |
| estimatedAmount | string/number | 否 | 运费，可传 `$3.57`、`3.57` 或数值 |
| shippingCompanyName | string | 否 | 物流商 |
| relatedGoodsInfoForAggregation | array | 是 | 子订单明细，至少一条 |

子订单对象字段：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| goodsName | string | 否 | 商品名称 |
| orderSn | string | 是 | 子订单号，幂等键 |
| parentOrderSn | string | 是 | 必须与外层主订单号一致 |
| skuQuantity | integer | 是 | 数量，必须大于 0 |
| spec | string | 否 | SKU/规格 |
| thumbUrl | string | 否 | HTTP/HTTPS 图片地址 |

一次请求展开后的子订单明细不得超过 1,000 条。

### 5.2 鉴权

配置项 `order.external.api-key` 从环境变量 `ORDER_DETAIL_API_KEY` 读取。配置为空时应用启动失败，避免线上误开放接口。

校验规则：

- 接口使用 `@SaIgnore` 跳过后台登录校验。
- 控制器读取 `X-API-Key`，使用常量时间比较验证密钥。
- API Key 不写入代码、数据库、响应或日志。
- 缺失或错误返回 HTTP 401。

### 5.3 幂等与事务

- 以 `orderSn` 唯一索引作为最终幂等保障。
- 数据库不存在 `orderSn` 时新增；已存在时覆盖本次接口管理的业务字段。
- 同一请求中重复出现同一 `orderSn` 时，以请求中最后一条为准。
- 所有展开、校验和数据库写入在一个事务中完成。
- 任意一条数据校验失败时整批回滚。
- 外层和子项的 `parentOrderSn` 不一致时拒绝整批请求。

### 5.4 响应

成功响应示例：

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {
    "received": 6,
    "created": 5,
    "updated": 1
  }
}
```

错误约定：

| HTTP 状态 | 业务码 | 场景 |
| --- | --- | --- |
| 400 | 400 | 参数格式、必填项、数量、金额、URL 或父子订单关系不合法 |
| 401 | 401 | API Key 缺失或错误 |
| 500 | 500 | 未处理系统异常，响应包含可查询的 8 位错误编号 |

参数错误信息需要指出数组下标和字段名，但不得回显 API Key 或完整商品数据。

## 6. 管理员接口

所有接口均使用 `@SaCheckRole(SystemConstants.SUPER_ADMIN_ROLE_KEY)`，由后端强制限制为超级管理员。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/order/details/list` | 分页查询 |
| GET | `/order/details/{id}` | 查看详情 |
| POST | `/order/details` | 新增单条明细 |
| PUT | `/order/details` | 修改单条明细 |
| DELETE | `/order/details/{ids}` | 单条或批量删除 |
| POST | `/order/details/export` | 按当前查询条件导出全部匹配数据 |

分页查询条件：

- 主订单号 `parentOrderSn`
- 子订单号 `orderSn`
- 店铺 ID `fulfillmentMallId`
- 下单工厂 `sendWarehouseName`
- 物流商 `shippingCompanyName`

管理员新增时若 `orderSn` 已存在则返回重复错误，不自动覆盖；修改时允许保留当前 `orderSn`，但不得占用其他记录的 `orderSn`。

## 7. Excel 导出

导出列严格按参考文件顺序：

1. 订单号：`parentOrderSn`
2. 店铺 ID：`fulfillmentMallId`
3. 运费：`estimatedAmount`
4. 下单工厂：`sendWarehouseName`
5. 物流商：`shippingCompanyName`
6. 子订单号：`orderSn`
7. 商品名称：`goodsName`
8. 主订单号：`parentOrderSn`
9. 数量：`skuQuantity`
10. SKU：`spec`
11. 图片地址：`thumbUrl`

“订单号”和“主订单号”均来自 `parentOrderSn`，这是对参考 Excel 的兼容要求。运费以数值形式导出，并使用两位小数格式。

## 8. 管理页面

菜单位置：`系统管理 > 订单明细`，组件路径：`order/detail/index`。菜单只分配给超级管理员。

页面组成：

- 查询区：主订单号、子订单号、店铺 ID、下单工厂、物流商。
- 操作区：新增、批量删除、导出、重置。
- 表格：主订单号、子订单号、店铺 ID、运费、工厂、物流商、商品名称、数量、SKU、缩略图、更新时间、操作。
- 商品名称和 SKU 超长时省略显示并提供悬浮提示。
- 图片地址非空时显示固定尺寸缩略图，点击打开预览；空值显示短横线。
- 新增/修改使用表单弹窗，显示单条明细的全部业务字段。
- 删除前显示二次确认。

页面沿用现有 Ant Design Pro 布局、间距、按钮和权限呈现方式，不新增独立设计系统。

## 9. 日志与审计

- 管理员新增、修改、删除、导出使用项目现有 `@Log` 操作日志。
- 外部导入记录调用时间、来源 IP、接收数量、新增数量、更新数量、结果和错误编号。
- 外部导入日志不记录 API Key、完整请求体或商品名称。
- 外部接口不是系统用户操作，不伪造管理员身份；其导入日志以“外部订单接口”作为来源。

## 10. 数据库与菜单脚本

新增可重复执行的 SQL 脚本，包含：

- `ord_order_detail` 表及索引。
- “订单明细”菜单。
- 页面所需的 list、query、add、edit、remove、export 权限字符。
- 超级管理员角色与菜单关联；重复执行不得产生重复记录。

后端仍以超级管理员角色校验作为最终授权依据，菜单关联只控制入口显示。

## 11. 配置与部署

- 在配置文件中声明 `order.external.api-key: ${ORDER_DETAIL_API_KEY}`。
- 本地 `.env.local` 配置仅用于本机联调的随机密钥，不写入接口文档。
- 示例环境文件只保留占位符，生产环境必须设置独立高强度密钥。
- 部署完成后使用不包含真实业务信息的样例验证接口。

## 13. 测试与验收

仅运行本功能及直接依赖的验证：

### 后端测试

- API Key 正确、缺失和错误。
- 嵌套请求展开和父子订单一致性。
- 金额字符串、纯数字字符串和数值转换。
- 单批 1,000 条允许、1,001 条拒绝。
- 同批重复 `orderSn` 取最后一条。
- 首次新增、重复调用更新及统计数量正确。
- 任一明细失败时整批回滚。
- 管理员 CRUD、唯一性校验和普通用户拒绝访问。
- Excel 表头、列顺序和筛选条件正确。

### 前端验证

- 订单页面 lint 和生产构建通过。
- 查询、分页、新增、修改、删除、批量删除和导出交互可用。
- 图片为空、有效 URL 和加载失败状态显示合理。
- 普通用户路由中不出现订单明细菜单。

### 部署验收

- 数据库脚本连续执行两次均成功且数据不重复。
- 前后端及依赖容器健康。
- 使用占位业务样例调用外部接口成功，并验证重复调用只更新不新增。
- 管理员页面显示入库数据，导出文件表头和列顺序与参考 Excel 一致。

## 14. 完成标准

- 外部调用方能够凭有效 API Key 批量保存订单明细。
- 相同 `orderSn` 重复提交不会产生重复数据。
- 只有超级管理员能够查看和操作订单明细管理功能。
- 管理页面 CRUD、查询、分页和 Excel 导出均可用。
- 操作及外部导入结果可追踪，敏感密钥不出现在日志和响应中。
- 项目内提供可直接交付调用方的 Markdown 接口文档。
