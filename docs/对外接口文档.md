# 对外接口文档

本文档是外部系统调用 Java 主站接口的统一入口。以下路径均以 `/prod-api` 为公网前缀；部署方提供实际域名。合作方 JSON 写入接口使用 `Content-Type: application/json`，通过请求头 `X-API-Key` 鉴权。密钥由管理员线下交付，不放入 URL、请求体或日志。

| 接口 | 方法与路径 | 密钥环境变量 |
| --- | --- | --- |
| 领取待检测图片 | `POST /prod-api/open-api/infringement/images/claim` | `IMAGE_INFRINGEMENT_API_KEY` |
| 回写单张图片检测结果 | `POST /prod-api/open-api/infringement/images/result` | `IMAGE_INFRINGEMENT_API_KEY` |
| 读取本地存储图片 | `GET /prod-api/open-api/infringement/images/{imageId}/content` | `IMAGE_INFRINGEMENT_API_KEY` |
| 查询 TRO 案件 | `POST /prod-api/open-api/tro/cases/query` | `TRO_API_KEY` |
| 补充 TRO 案件 | `POST /prod-api/open-api/tro/cases/supplement` | `TRO_API_KEY` |
| 批量写入订单明细 | `POST /prod-api/open-api/order-details/batch` | `ORDER_DETAIL_API_KEY` |
| 查询店铺 ID 是否存在 | `GET /prod-api/i/q/r?store_id={店铺ID}` | 无，返回布尔值 |
| 读取上架表格成品图 | `GET /prod-api/store/listing-exports/public-results?key={成品Key}` | 无，读取地址由已生成的上架表格提供 |

通用 JSON 响应为 `{"code":200,"msg":"操作成功","data":...}`。鉴权失败返回 HTTP 401；参数错误返回 HTTP 400；领取凭证失效或结果冲突返回 HTTP 409；系统异常返回 HTTP 500 和错误编号。

## 图片侵权检测

### 1. 领取待检测图片

请求体为空：

```http
POST /prod-api/open-api/infringement/images/claim
X-API-Key: <图片接口密钥>
```

每次最多返回 200 张；不足 200 张时返回实际数量，没有待领图片时 `data` 为 `[]`。只领取已进入正式图库、内部图片解析已成功且尚无三方侵权检测结果的图片；即使历史内部检测已有风险等级，仍可领取。数据库事务中使用 `FOR UPDATE SKIP LOCKED` 原子领取，并为本次领取写入凭证和时间；并发请求不会在有效期内领取同一张图片。

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": [
    {
      "imageId": "1234567890123456789",
      "imageUrl": "https://example-oss/image.jpg?...",
      "claimToken": "a2dcac55-17fa-4a28-a945-840af462067c",
      "expiresAt": "2026-09-30 10:00:00"
    }
  ]
}
```

`imageId` 是图片唯一 ID，按 JSON 字符串返回，避免 JavaScript 处理 64 位整数时丢失精度。`imageUrl` 在 OSS 模式下是有效期与领取期相同的临时签名 URL，可直接 GET。在本地存储模式下返回相对路径 `/prod-api/open-api/infringement/images/{imageId}/content`，请以主站域名拼接，并同时带 `X-API-Key` 和 `X-Claim-Token: <claimToken>` 请求头。`expiresAt` 使用服务端本地时区。调用方应在过期前下载图片；过期后图片可被再次领取。领取超时由 `IMAGE_INFRINGEMENT_LEASE_MINUTES` 配置，默认 1440 分钟。

### 2. 回写单张检测结果

每张图片检测完后单独调用：

```http
POST /prod-api/open-api/infringement/images/result
X-API-Key: <图片接口密钥>
Content-Type: application/json
```

```json
{
  "imageId": "1234567890123456789",
  "claimToken": "a2dcac55-17fa-4a28-a945-840af462067c",
  "riskLevel": "needs_review",
  "riskReason": "疑似侵权，需人工确认",
  "CaseNumber": ["26-cv-26730", "26-cv-26731"],
  "verificationUrls": ["https://example.com/evidence/123"]
}
```

| 字段 | 要求 |
| --- | --- |
| `imageId` | 必填，领取接口返回的图片 ID |
| `claimToken` | 必填，领取接口返回的凭证；不同批次重领会更换 |
| `riskLevel` | 必填，`high`、`low`、`needs_review`，大小写不敏感；系统存为 `HIGH`、`LOW`、`NEEDS_REVIEW` |
| `riskReason` | 可为空，最多 255 字符 |
| `CaseNumber` | 可省略或传空数组，最多 100 个案号，每项最多 32 字符 |
| `verificationUrls` | 暂定字段名，可省略或传空数组，最多 100 条 HTTP/HTTPS URL，每项最多 2000 字符；字段名最终确定后需同步更新接口与本文档 |

首次写入成功返回 `data: null`；同一凭证、同一内容重复提交也返回成功。凭证已被超时重领替换、图片已删除或相同凭证提交了不同结果时返回 HTTP 409。结果写入图片当前关联的侵权明细，现有页面继续读取风险等级、原因和 TRO 案号；验证 URL 仅入库预留，当前页面不展示。

网络超时后可用同一请求重试。领取超时后尚未被重新领取的结果仍可回写；一旦重新领取，旧凭证失效。系统不会把分析失败视为“低风险”。

## TRO 案件

### 3. 查询案件

```http
POST /prod-api/open-api/tro/cases/query
X-API-Key: <TRO接口密钥>
Content-Type: application/json
```

```json
{"plaintiffName":"Omega SA","plaintiff":"Omega SA","caseNoFormat":["26-cv-26647","26-cv-26648"]}
```

三个字段都可选，但至少提供一个。`caseNoFormat` 可为单个字符串或字符串数组；多个条件按“或”匹配。权利人字段会忽略大小写和空白，与案件的 `plaintiff` 或 `plaintiffNames` 任一名称匹配。无结果时返回空数组。

```json
{"code":200,"msg":"操作成功","data":[{"plaintiffNamesStr":"Omega SA，Omega中文","plaintiff":"Omega SA","caseNoFormat":"26-cv-26647"}]}
```

### 4. 补充案件

```http
POST /prod-api/open-api/tro/cases/supplement
X-API-Key: <TRO接口密钥>
Content-Type: application/json
```

```json
{
  "caseNoFormat": "26-cv-26730,26-cv-26731,26-cv-26732",
  "plaintiff": "权利人信息",
  "plaintiffCn": "作者信息",
  "plaintiffNames": ["BESTSKY商标", "ALBION BRAND FOUNDRY LTD"]
}
```

四个字段必填。`caseNoFormat` 用英文逗号分隔，逐项去首尾空格、去重，最多 200 个案号，每个最多 32 字符。`plaintiff` 和 `plaintiffCn` 最多 255 字符；作者与权利人相同时两个字段传相同内容。`plaintiffNames` 最多 100 项，每项最多 255 字符，去空白和重复项后不能为空。

按“案件号 + `plaintiff`”唯一键逐案幂等补充。已有案件只更新 `plaintiffCn` 与 `plaintiffNames`，保留案件名称、法院、日期等其他资料；不存在时新增。全部案号在一个事务中处理，任一失败整体回滚。成功时 `data` 是去重后的处理案号数，例如 `3`。

## 订单明细

### 5. 批量新增或更新

```http
POST /prod-api/open-api/order-details/batch
X-API-Key: <订单接口密钥>
Content-Type: application/json
```

请求体是主订单数组。主订单必填 `parentOrderSn`（最多 64 字符）和非空 `relatedGoodsInfoForAggregation`；子订单必填 `orderSn`、`parentOrderSn`（均最多 64 字符）及正整数 `skuQuantity`。父子 `parentOrderSn` 必须一致。可选字段包括主订单的 `parentOrderTimeStr`、`sendWarehouseName`、`fulfillmentMallId`、`estimatedAmount`、`shippingSettleAmount`、`shippingCompanyName`、`siteName`，以及子订单的 `goodsName`、`salesSettleAmount`、`customized_products`、`spec`、`thumbUrl`。展开后的子订单最多 1000 条，`orderSn` 是幂等键；同请求重复时最后一条生效。整批写入在一个事务中完成。

```json
[
  {
    "parentOrderSn": "PO-001",
    "siteName": "US",
    "relatedGoodsInfoForAggregation": [
      {"orderSn":"SO-001","parentOrderSn":"PO-001","skuQuantity":1,"goodsName":"示例商品"}
    ]
  }
]
```

成功响应 `data` 包含 `received`、`created`、`updated` 三个计数。完整字段长度、金额格式和错误示例见[订单明细外部接口文档](订单明细外部接口文档.md)。

## 维护说明

`/i/q/r` 仅用于已配置的店铺 ID 存在性查询；缺失或空 `store_id` 返回 `false`。上架表格成品图接口仅接受系统生成的 `store/results/...` Key，不接受任意文件路径。渲染 Worker 使用的 `/store/internal/**` 是内部调用接口，单独以 `X-Render-Worker-Token` 鉴权，不交付给合作方。

主站上线前先执行 `server/script/sql/migrations/20260929_external_infringement.sql`，再配置新的图片接口密钥与领取超时；本地 Docker Compose 的 `migrate` 服务会执行这份增量迁移。密钥不要写进文档或仓库。新增对外接口时，请同时更新本页的目录、请求与响应示例及错误语义。
