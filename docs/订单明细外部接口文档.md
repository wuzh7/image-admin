# 订单明细外部接口文档

## 1. 接口概览

- 接口用途：外部系统批量新增或更新订单明细。
- 请求方法：`POST`
- 请求路径：`/open-api/order-details/batch`
- 请求类型：`application/json`
- 鉴权方式：请求头 `X-API-Key`
- 单次上限：展开后的子订单明细最多 1,000 条。

生产地址由部署方提供，例如：

```text
http://47.114.40.197/prod-api/open-api/order-details/batch
```

## 2. 鉴权

每次请求必须携带管理员分配的 API Key：

```http
X-API-Key: <由管理员提供的API_KEY>
```

API Key 不应出现在 URL、请求体、日志或公开代码仓库中。缺失或错误时接口返回 HTTP 401。

## 3. 请求参数

请求体是主订单数组。每个主订单通过 `relatedGoodsInfoForAggregation` 携带一条或多条子订单明细。

### 3.1 主订单字段

| 字段 | 类型 | 必填 | 最大长度 | 说明 |
| --- | --- | --- | --- | --- |
| parentOrderSn | string | 是 | 64 | 主订单号 |
| sendWarehouseName | string | 否 | 128 | 下单工厂 |
| fulfillmentMallId | string | 否 | 64 | 店铺 ID |
| estimatedAmount | number/string | 否 | - | 运费，可传 `3.57`、`"3.57"` 或 `"$3.57"`，不得为负数 |
| shippingSettleAmount | number/string | 否 | - | 订单运费预计冲回，格式同运费，不得为负数 |
| shippingCompanyName | string | 否 | 128 | 物流商 |
| siteName | string | 否 | 128 | 销售站点；该主订单下的全部子订单明细使用此值 |
| relatedGoodsInfoForAggregation | array | 是 | - | 子订单明细，至少一条 |

### 3.2 子订单字段

| 字段 | 类型 | 必填 | 最大长度 | 说明 |
| --- | --- | --- | --- | --- |
| goodsName | string | 否 | 1000 | 商品名称 |
| orderSn | string | 是 | 64 | 子订单号，全局唯一，也是幂等键 |
| parentOrderSn | string | 是 | 64 | 主订单号，必须与外层 `parentOrderSn` 一致 |
| skuQuantity | integer | 是 | - | 数量，必须大于 0 |
| salesSettleAmount | number/string | 否 | - | 子订单预计回款，格式同运费，不得为负数 |
| customized_products | string | 否 | 255 | 是否定制；不校验内容，原样保存到当前子订单明细 |
| spec | string | 否 | 512 | SKU/规格 |
| thumbUrl | string | 否 | 1000 | 图片地址，只允许 HTTP 或 HTTPS 地址 |

## 4. 请求示例

```json
[
  {
    "parentOrderSn": "PO-20260905-001",
    "sendWarehouseName": "示例工厂",
    "fulfillmentMallId": "SHOP-001",
    "estimatedAmount": "$3.57",
    "shippingSettleAmount": "$2.22",
    "shippingCompanyName": "Example Express",
    "siteName": "US",
    "relatedGoodsInfoForAggregation": [
      {
        "goodsName": "示例商品",
        "orderSn": "SO-20260905-001",
        "parentOrderSn": "PO-20260905-001",
        "skuQuantity": 1,
        "salesSettleAmount": "$10.51",
        "customized_products": "是",
        "spec": "Black / L",
        "thumbUrl": "https://example.com/images/demo.jpg"
      }
    ]
  }
]
```

## 5. 成功响应

HTTP 状态：`200 OK`

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {
    "received": 1,
    "created": 1,
    "updated": 0
  }
}
```

| 字段 | 说明 |
| --- | --- |
| received | 请求中收到的子订单明细数量；同一请求内重复的 `orderSn` 仍计入收到数量 |
| created | 新增入库数量 |
| updated | 按 `orderSn` 更新的数量 |

## 6. 幂等与事务规则

- `orderSn` 是幂等键。数据库中不存在时新增，已存在时用本次数据更新原记录。
- 同一请求内多次出现相同 `orderSn` 时，以最后一条数据为准。
- 整个请求在同一事务内处理。任意一条校验或写入失败时，本次请求全部回滚。
- 调用方可在网络超时后使用原请求重试，不会产生相同 `orderSn` 的重复记录。

## 7. 错误响应

### 7.1 API Key 缺失或错误

HTTP 状态：`401 Unauthorized`

```json
{
  "code": 401,
  "msg": "API Key无效",
  "data": null
}
```

### 7.2 参数校验失败

HTTP 状态：`400 Bad Request`

```json
{
  "code": 400,
  "msg": "orders[0].relatedGoodsInfoForAggregation[0].skuQuantity必须大于0",
  "data": null
}
```

常见原因包括：请求数组为空、明细超过 1,000 条、主订单号缺失、父子订单号不一致、数量不大于 0、金额格式错误或图片地址不是 HTTP/HTTPS 地址。

### 7.3 系统异常

HTTP 状态：`500 Internal Server Error`

```json
{
  "code": 500,
  "msg": "发生系统异常，请联系管理员 [错误编号: 12345678]",
  "data": null
}
```

联系管理员时请提供响应中的错误编号。服务器日志会记录对应异常，但不会记录 API Key 和完整请求体。

## 8. curl 示例

```bash
curl -X POST "http://47.114.40.197/prod-api/open-api/order-details/batch" \
  -H "Content-Type: application/json" \
  -H "X-API-Key: <由管理员提供的API_KEY>" \
  --data '[{"parentOrderSn":"PO-20260905-001","sendWarehouseName":"示例工厂","fulfillmentMallId":"SHOP-001","estimatedAmount":"$3.57","shippingSettleAmount":"$2.22","shippingCompanyName":"Example Express","siteName":"US","relatedGoodsInfoForAggregation":[{"goodsName":"示例商品","orderSn":"SO-20260905-001","parentOrderSn":"PO-20260905-001","skuQuantity":1,"salesSettleAmount":"$10.51","customized_products":"是","spec":"Black / L","thumbUrl":"https://example.com/images/demo.jpg"}]}]'
```

## 9. Excel 导出列

后台“订单明细”页面导出的 Excel 列顺序如下：

1. 订单号
2. 店铺ID
3. 运费
4. 订单运费预计冲回
5. 子订单预计回款
6. 销售站点
7. 是否定制
8. 下单工厂
9. 物流商
10. 子订单号
11. 商品名称
12. 主订单号
13. 数量
14. SKU
15. 图片地址

“订单号”和“主订单号”均对应外层 `parentOrderSn`，用于保持与现有 Excel 模板一致。
