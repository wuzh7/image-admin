# 图片管理系统项目总览

> 更新时间：2026-09-16。本文是交给新 Agent 的快速入口；以代码和运行配置为准，不包含密钥、账号、IP 或业务数据。

## 目标与边界

这是面向小团队上线的图片管理 MVP。它完成“上传图片、SSCD 去重、人工确认、正式图库、侵权风险标记、订单明细管理”。

- 图片去重与侵权风险是两条独立链路：风险检测失败绝不能被写成低风险，也不阻止已确认的图片进入正式图库。
- 只支持可完整解码的 JPEG、PNG、WebP；GIF 和损坏/超大/超像素文件仍应拒绝。
- 文件名扩展名不可信：以真实解码格式作为保存后的 MIME 类型。扩展名不一致本身不应导致检测失败。
- 默认不执行 Git add、commit、push；工作区经常有用户的未提交改动，修改前先检查 `git status --short`。

## 技术栈与目录

| 区域 | 位置 | 说明 |
| --- | --- | --- |
| 后端启动模块 | `server/wuzh-admin` | JDK 21、Spring Boot、Maven |
| 图片核心 | `server/wuzh-modules/wuzh-image` | 上传、SSCD、Qdrant、审核、入库、Gemini 风险任务 |
| 订单模块 | `server/wuzh-modules/wuzh-order` | 订单明细和外部接口 |
| 前端 | `web` | React 19、TypeScript、Ant Design、Umi Max、pnpm |
| 本地部署 | `server/deploy/local` | Docker Compose 与 PowerShell 脚本 |
| 生产部署 | `server/deploy/prod` | Compose、macOS 发布脚本 `publish-prod.sh`、发布产物目录 |

依赖：MySQL 保存业务数据；Redis 仅供系统既有能力，不参与图片任务；Qdrant 保存 SSCD 向量；生产图片使用 OSS 浏览器直传，后端以 RAM 角色读取；主服务直接调用火山方舟。禁止把任何 AI API Key 写入代码、文档或前端。

## 图片主流程

```text
浏览器选择图片
  -> 创建批次和 OSS 直传会话；AI 分析固定使用火山方舟
  -> OSS 保存原文件
  -> 后端下载并完整解码，记录真实 MIME、尺寸、SHA-256
  -> SSCD 特征与 Qdrant/本批次召回
  -> 低于阈值：APPROVING -> 正式图库 + Qdrant
  -> 达到阈值或完全重复：WAIT_REVIEW -> 人工选择确认
  -> 确认后：正式图库 + Qdrant

正式入库与 AI 图片分析并行；图库展示分析状态（等待、完成、失败）。风险等级和原因由后续三方接口更新。
```

### 关键规则

- 默认相似度阈值为 `0.60`；低于阈值自动入库，高于或等于阈值人工审核。
- 完全相同的 SHA-256 图片不得重复入库。
- 每张高相似图片保存并展示自己的 Top30 精排候选；前端按页显示候选图。
- SSCD 当前每图使用 5 个查询视图。不要擅自改算法、阈值、FIFO 顺序或召回数量。
- 图片分析经火山方舟 Responses API 单次调用 `doubao-seed-2-0-lite-260428`，仅返回英文描述与五类中文标签，不生成风险等级、原因或案号。
- 唯一提示词由 `server/deploy/image_analysis_prompt.txt` 配置，随后端镜像打包；修改提示词需重新发布后端。历史风险结果仍可查看。
- 普通用户可导出分析完成且风险尚未评估的图片；历史 LOW 图片仍可导出。渲染使用同一准入规则，后续风险等级更新为 HIGH 后不再满足该规则。

## 主要数据与状态

| 表/集合 | 用途 |
| --- | --- |
| `img_batch` | 上传批次与总体进度 |
| `img_asset` | 原图、相似结果、入库状态、真实 MIME、分析任务引用 |
| `img_category` | 图片类目 |
| `infringement_scan_task` / `infringement_scan_item` | 图片分析任务与历史风险结果 |
| `infringement_call_log` | 每次 AI 调用的原始返回、usageMetadata 及执行方式 |
| Qdrant `image_sscd_v1` / `image_sscd_staging_v2` | 正式图库与批次去重向量 |

常见图片状态：`UPLOADING` → `UPLOADED` → `APPROVING` 或 `WAIT_REVIEW`；正式图库为 `APPROVED`。处理或读取技术失败为 `FAILED`；入库失败为 `APPROVAL_FAILED`。

## 页面与接口入口

- 图片上传与人工复核：`web/src/pages/image/dedup/index.tsx`
- 正式图库：同页的图库路由/动态页面映射
- 图片 AI 分析任务：`web/src/pages/image/infringement/`
- 图片 API：`ImageController`、`ImageService`、`ImageTaskRunner`
- 动态菜单页面映射：`web/src/pages/dynamicPage.tsx` 的 `migratedPages`；新增或移动页面必须同步这里。
- 生产前端通过 Nginx 的 `/prod-api/` 访问后端，不要在前端硬编码 `localhost:8080`。

## 配置与部署

- 本地配置：`server/wuzh-admin/src/main/resources/application-local.yml`、`server/deploy/local/compose.yml`。
- 生产配置：`server/wuzh-admin/src/main/resources/application-prod.yml`、`server/deploy/prod/compose.yml`、`server/deploy/prod/.env.oss.example`。
- 生产发布：macOS 在 `server/deploy/prod/` 使用 `./publish-prod.sh`；Windows 可继续使用 `publish-prod.ps1`。发布前核对环境变量，不输出或提交 `.env` 内容。
- 火山方舟配置：杭州主服务的生产 `.env` 配置 `ARK_API_KEY`；后端镜像包含图片分析提示词，不再部署 AI Gateway。
- 运行参数：`IMAGE_TASK_WORKERS`、`IMAGE_FEATURE_BATCH_SIZE`、`IMAGE_UPLOAD_CONCURRENCY`。调整性能时一次只改一个参数，并用同一批图片比较 `图片批次性能` 日志；主要耗时通常是 SSCD 推理。

## 验证清单

前端改动至少执行：

```powershell
cd web
pnpm lint
```

图片后端改动至少执行定向 Maven 测试；删除或移动 Java 类后使用 `clean package`，避免旧 class 残留：

```powershell
cd server
mvn -pl wuzh-modules/wuzh-image -am "-Dprofiles.active=local" "-Dmaven.test.skip=false" "-DskipTests=false" "-Dtest=ImageTaskRunnerTest,ImageAdmissionWorkerTest,InfringementWorkerTest,ImageServiceTest" "-Dsurefire.failIfNoSpecifiedTests=false" test
mvn -pl wuzh-admin -am "-Plocal,djl-linux" "-DskipTests" clean package
```

涉及 Compose、菜单、路由、环境变量或 OSS 时，还需重建对应容器并从真实页面验证：上传、自动/人工入库、图库预览、风险状态和手动重试。

## 协作提示

1. 先读根目录 `AGENTS.md`，再读本文件和触及模块的测试。
2. 保留无关未提交改动；只修改需求直接涉及的文件。
3. 生产结论必须通过公网路径、实际页面/API 和容器日志证明，不能只看本地容器。
4. 图片数据清理只在用户明确授权时进行，并且只清理图片相关表、文件和 Qdrant 集合，保留账号、角色、类目、订单和系统配置。
